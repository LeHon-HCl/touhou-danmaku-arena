# 素材目录 · 改图改音指南

这个目录是**给人改素材用的**，不是给程序读的源码。替换图片或音效不需要改任何代码：
把文件按下面的名字放进来，刷新页面就能听到、看到。

```
assets/
├── README.md          ← 你正在看的这份
├── images/            ← 图片（PNG）
│   └── README.md      ← 文件名与尺寸速查表
└── audio/             ← 音频（.ogg / .mp3）
    └── README.md      ← 文件名与时长速查表
```

---

## 1. 三分钟上手

1. 打开 `assets/images/`，按 [images/README.md](images/README.md) 的文件名表放进 PNG。
2. 打开 `assets/audio/`，按 [audio/README.md](audio/README.md) 的文件名表放进 `.ogg` 或 `.mp3`。
3. 刷新浏览器页面。

没放的、或者名字打错的，游戏**不会崩**：缺图片就用代码画的占位图，缺音效就用代码合成的占位音。

> 想看当前哪些素材真正生效了：按 F12 打开控制台，启动时会输出一行
> `[素材] 图片 3/12 来自文件，其余用占位图；音效 6/6 来自文件`。

## 2. 图片怎么改

### 2.1 硬规则

| 项目   | 要求                                                                         |
| ------ | ---------------------------------------------------------------------------- |
| 格式   | **PNG** 最佳（带透明通道，背景透明、不要白底）；`.jpg` / `.jpeg` / `.webp` / `.avif` / `.gif` / `.bmp` 也能读，但没有透明通道会显示成一块方形背景 |
| 尺寸   | 推荐与速查表一致（角色 48×48、瓦片 32×32、子弹 12×12、道具 24×24、粒子 4×4） |
| 文件名 | 按表来，**区分大小写**（`char_reimu.png` ≠ `Char_Reimu.png`）              |
| 像素风 | 直接按目标尺寸画；不要先画 480×480 再缩到 48×48，边缘会糊                    |

来不及按目标尺寸导出也能跑：尺寸不一致时程序会**等比缩放并居中**到清单尺寸（多出来的部分保持透明），
控制台同时打印一条尺寸警告——看到警告就说明该改图了。

扩展名也不用死磕：清单写的是 `char_reimu.png`，你放的是同名的 `char_reimu.jpg`，
加载器会自动匹配，并在控制台提示 `[素材] 已自动匹配同名文件：…`。
文件名主体（`char_reimu`）仍然要一致，`char_reimu (1).png` 这种是认不出的。

### 2.2 角色图（`char_*.png`）

- 正面视角，不是俯视头顶；左右朝向靠程序水平翻转，所以**只画一个朝向**
- 角色本体占约 40×44，四周至少留 **2px 空白**
  留白是给红色描边留的位置：敌我辨识的描边画在贴图外侧，贴边会被裁掉
- 左右尽量对称。允许细节级不对称（蝴蝶结偏一侧、帽子星星位置），
  不要结构级不对称（左红右蓝、单边披风）—— 翻转后会像换了一个人
- 不同角色请保持相近的身高与头部比例，否则同屏看起来不像同一个游戏

### 2.3 地图瓦片（`tile_*.png`）

- 32×32，**必须能无缝平铺**：左边缘接右边缘、上边缘接下边缘不能看出缝
- 地面偏暗、墙体偏亮：本作是稀疏弹道竞技，玩家需要一眼分清"能走"和"挡子弹"
- 墙体有 4px 顶面高光会更立体（占位图就是这么画的，可参考）

### 2.4 道具（`item_*.png`）

- 24×24，图形尽量占满，留 1–2px 内边距
- 每个道具有固定主题色（见 `shared/src/config/items.ts` 里的 `color`），建议贴合：
  治疗=绿、防御=蓝、攻击=橙、射速=黄、移速=紫
- 形状要能被一眼分辨（不要五个都是圆球）

### 2.5 粒子和子弹

- `fx_particle.png` 会被**染色 + 缩放**，画成白色实心方块/圆点即可，不要带颜色
- `bullet_player.png` 12×12，需要有外发光感，保证在深色地面和亮色墙面上都看得见

## 3. 音频怎么改

### 3.1 硬规则

| 项目          | 要求                                                                            |
| ------------- | ------------------------------------------------------------------------------- |
| 格式          | **`.ogg`** 优先，也可用 `.mp3`（同名时优先 ogg）                                |
| 不要用 `.wav` | `.gitignore` 忽略了 `*.wav`，放进去不会进版本库，别人拉代码就没有               |
| 文件名        | 严格按 [audio/README.md](audio/README.md)，例如 `shoot.ogg`、`shield_break.ogg` |
| 声道          | 单声道即可。左右声道由程序按声源位置实时计算，素材里做立体声反而会打架          |
| 响度          | 先把所有音效归一化到同一响度，再靠 `BASE_VOLUME` 微调                           |

### 3.2 节奏与时长

| 音效     | 建议时长   | 说明                                            |
| -------- | ---------- | ----------------------------------------------- |
| 开枪     | 0.06–0.12s | 连射时会被高频触发，超过 0.15s 就会糊成一片噪音 |
| 命中     | 0.05–0.10s | 短促、高频，才有"打中了"的反馈                  |
| 护盾破碎 | 0.15–0.30s | 要明显区别于普通命中                            |
| 击倒     | 0.25–0.50s | 可以低频下坠，情绪最重                          |
| 受伤     | 0.10–0.20s | 玩家自己挨打时的提示，要刺耳一点                |
| 拾取     | 0.10–0.20s | 上扬感，正反馈                                  |

### 3.3 避免削波

导出前把峰值控制在 **-1 dBFS 以内**。游戏里会叠加上距离衰减和位置声像，
素材本身接近 0 dB 时，多人同时开枪很容易破音。

## 4. 常见问题

**Q：放了文件但没生效？**

1. 检查文件名是否一致（下划线、不要有空格、不要 `char_reimu (1).png`；扩展名不同会自动兜底，文件名主体必须一致）
2. 检查是不是放到了 `assets/` 根目录而不是 `assets/images/` 或 `assets/audio/`
3. 刷新页面（浏览器缓存了旧图时按 Ctrl+F5 强制刷新）
4. 看控制台第一行的 `[素材] ...` 统计，确认程序有没有捡到你的文件
5. 还是没生效就看控制台里有没有 `[素材] 尺寸不符` / `[素材] 已自动匹配同名文件` 的提示

**Q：图片显示得很糊 / 有白边？**

- 糊：原图不是像素画，或者画完被缩放插值过。请按目标尺寸直接绘制
- 白边：PNG 边缘有半透明像素。像素风要求 alpha 二值化——要么全透明要么不透明

**Q：改了图但敌我描边变成一圈毛？**
同上的 alpha 问题。半透明边缘会让程序生成的描边沿着毛刺走。

**Q：能改文件名吗？**
不能。文件名是程序查找素材的唯一依据，改了就当成"文件不存在"来处理（回退到占位图）。
确实需要改名时，改 `client/src/assets/manifest.ts` 里的 `file` 字段。

**Q：想加一个新道具 / 新角色？**
那不只是素材的事，还要改 `shared/src/config/` 里的配置表。先加配置，再来这里补图。

**Q：生产构建会带上素材吗？**
会。`npm run build` 会把 `assets/images`、`assets/audio` 复制到 `dist/` 下的同名目录，
部署时整个 `dist/` 一起发出去即可，不需要额外配置。

## 5. 合规提醒

本项目的定位是**非商业同人作品，只在同好群内部分发**（见仓库根目录 README）。

- 优先使用 **CC0 / 开源协议**素材，并在提交说明里登记来源与协议
- 不要使用来源不明的网络素材（包括"随手搜到的 PNG / BGM"）
- AI 生成的图请保留生成记录；需要人工修整的部分（眼睛、轮廓）按 `docs/art-spec.md` 的流程处理
